# Career Capture

> 趁热记录，别等到写简历才回忆。

按约定定位履历库：`RESUMAKER_VAULT` → `~/.config/resumaker/config.json` → `./career/`。
**先读 `<vault>/VAULT.md`**，文件格式以它为准。

## 三种模式

### A. 随手记（最常用）

用户刚做完一件事，或者在对话里提到一件值得记的事。

1. 用 2～4 个问题补全关键信息，**不要一次问太多**：
   - 结果是什么？有数字吗？数字从哪里看到的（看板、PR、报告）？
   - 你具体负责哪部分？
   - 有没有什么取舍或踩坑，值得面试时讲？
2. 确定它挂在哪个 `experience` / `project` 下面；容器不存在就顺手建一个。
3. 写入 `achievements/<YYYY-MM>-<slug>.md`，`status: confirmed`（用户亲口说的就算确认）。
4. 至少写一个「讲法」。能看出两个不同角度的话写两个。
5. 用一句话回报：记了什么、存在哪、还缺什么（比如"数字没有出处，回头补个截图到 evidence/"）。

如果用户只是随口一提、信息很少，就写进 `inbox/`（`status: draft`, `captured_by: career-capture`），别为了凑完整打断用户的工作。

**如果你正在帮用户完成一项工作**（写代码、做方案），任务完成且结果明确时，可以顺口问一句"要不要记进履历？"。一次会话最多问一次。

### B. 批量导入（冷启动）

来源可能是：旧简历（PDF/Word/HTML）、LinkedIn 导出、GitHub 主页或仓库、周报/月报、述职或晋升材料、个人博客。

1. 通读全部材料，先列出**候选清单**给用户看：

   | # | 成果 | 归属 | 有数字？ | 疑问 |
   |---|---|---|---|---|

2. 用户确认（可以删减、合并）之后再落盘：
   - 容器（experiences、projects）先建
   - 每条成果一个文件；材料里明确写着的内容直接设为 `confirmed`，靠推断补出来的放进 `inbox/`
   - 旧简历上的数字：`source` 写"旧简历"，`verified: false`，提醒用户之后补证据
3. `profile.md` 里的教育背景、联系方式等基本信息一起补齐。
4. 最后列出"最值得补细节的 3 条"，这些是将来面试最可能被深挖的地方。

GitHub 导入可以用 `gh` 读取用户自己仓库的 README、star 数、主要语言和合并的 PR。**只读公开信息**，不要替用户做任何写操作。

### C. 访谈（什么材料都没有）

做一次 15 分钟左右的轻量访谈，目标是先记 3～5 件**最拿得出手**的事，不求全。

- 从时间线开始："最近一段经历是什么？在那儿做过最有成就感的一件事是什么？"
- 每件事追问三层：**为什么做 → 你做了什么 → 结果怎样**
- 用户说不出数字时，帮他找替代：耗时、规模、覆盖人数、事故数、"从 X 到 Y"
- 应届或转行的用户：课程项目、竞赛、开源、社团、实习都算

每聊完一件就落盘一件，不要等到最后。

## 写作要求

- 正文用用户自己的话，不要包装成简历腔。**包装是 resume-tailor 的事，库里存原始素材。**
- 数字照实记录，不确定就标 `verified: false`
- 涉及公司内部信息时，问一下保密等级，默认 `internal`
- 文件名、id 一律用 kebab-case；时间前缀用这件事发生的月份，不是记录的日期
