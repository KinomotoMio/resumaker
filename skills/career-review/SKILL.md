# Career Review

> 自动采集只负责起草，**进入成果库必须经过用户点头**。

按约定定位履历库：`RESUMAKER_VAULT` → `~/.config/resumaker/config.json` → `./career/`。先读 `<vault>/VAULT.md`。

## 1. 过一遍草稿箱

列出 `inbox/` 里的草稿，按时间排序，给用户一张总览表：

| # | 草稿 | 来源 | 建议 |
|---|---|---|---|
| 1 | 修复支付回调幂等问题 | career-harvest · 2026-10-09 | ✅ 值得收（有明确结果） |
| 2 | 调研了三个向量数据库 | career-harvest · 2026-10-10 | 🔀 并入 #4，同一件事 |
| 3 | 改了 README 错别字 | career-harvest · 2026-10-11 | 🗑 建议丢弃 |

**你的判断标准**：有没有结果？能不能写成一条 bullet？面试时能不能讲 3 分钟？
都不满足的，建议丢弃，但最终由用户决定。

## 2. 逐条处理用户想收的

对每一条：

1. 补问缺失的关键信息，**一次只问最关键的 1～2 个问题**（通常是数字和出处）
2. 和 `achievements/` 里已有的成果比对：是同一件事的后续，就**合并进原文件**（追加，不覆盖）；是新的一件事，就新建文件
3. 确认保密等级
4. 补至少一个「讲法」
5. 移到 `achievements/`，改成 `status: confirmed`，去掉 `captured_by`
6. 丢弃的草稿直接删掉。草稿只是线索，不需要留档

用户说"都收了"的时候，也要逐条快速确认数字和保密等级，不能直接批量移动。

## 3. 健康检查（每次 review 顺手做）

扫一遍整个库，报告这些问题（只报告，不擅自修改）：

- 成果引用了不存在的 `experience` / `project`
- 有 `verified: false` 的指标，而且已经超过 3 个月，提醒用户补证据，否则就该考虑删掉
- 某段经历下面一条成果都没有
- 某个成果没有任何「讲法」
- 最近 30 天没有任何新成果（温和地提醒，不要说教）

## 4. 收尾

一句话总结：收了几条、合并了几条、丢了几条，库里现在一共多少条成果。
如果履历库是 git 仓库，提议提交一次（例如 `review: +3 achievements`），**得到同意再提交**。
