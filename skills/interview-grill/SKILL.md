# Interview Grill

> 面试官是看着你的简历出题的。写进简历的每一个字，都要能被追问。

按约定定位履历库：`RESUMAKER_VAULT` → `~/.config/resumaker/config.json` → `./career/`。先读 `<vault>/VAULT.md`。

## 输入

一个投递目录：读 `resume.yaml`、`jd.md`、`match.md`，再顺着每条 bullet 的 `from` 读对应的成果文件，尤其是 `## 深挖` 部分。
用户只给了一份简历、没有投递目录时，也能用，只是没法对照 JD。

## 生成深挖卡（grill.md）

### 1. 逐条 bullet 设计追问链

面试官的追问通常是一层层往下挖的：

1. **是什么**：这个系统 / 项目是做什么的？规模多大？
2. **你做了什么**：你具体负责哪部分？团队里其他人做了什么？
3. **为什么**：为什么选这个方案？考虑过哪些替代方案？
4. **怎么验证**：这个数字是怎么测的？基线是什么？有没有其他因素影响？
5. **边界**：遇到过什么问题？哪里没做好？如果重来会怎么做？

每条 bullet 写 3～5 个最可能被问的问题，**按被问到的可能性排序**。
带数字的 bullet，一定要有一个"这个数字怎么来的"。

### 2. 给每个问题配上素材

从成果文件里找答案要点。找不到的，明确标出 ⚠️：

```markdown
### 「主导 WebSocket 网关连接模型重构，P99 延迟 320ms → 85ms」
来源：achievements/2025-03-ws-gateway-perf.md

**Q1 为什么每连接一个协程不行？瓶颈具体在哪？**
- 素材：百万连接时协程栈内存约 8GB；GC 停顿导致 P99 毛刺（见「背景」）
- 建议讲法：先讲现象（P99 毛刺）→ 定位过程（pprof 看到……）→ 根因

**Q2 P99 是怎么测的？**
- 素材：Grafana 看板，晚高峰 7 天平均（evidence/2025-03-ws-p99.png）

**Q3 epoll + 协程池在 Go 里怎么实现？和 netpoll 有什么区别？**
- ⚠️ 库里没有记录。建议补充：……
```

### 3. 结合 JD 补充问题

- JD 的核心职责里，有哪些简历上没直接体现、但面试很可能考的？
- `match.md` 里的缺口，面试官问到时怎么应对？
- 岗位相关的八股题（比如高并发岗必问的限流算法），只列题目和用户可以联系上的成果，不展开讲。

### 4. 风险清单

放在 `grill.md` 最前面：

- 🔴 **高风险**：素材不足以支撑的 bullet、`verified: false` 的数字、"主导"这类可能被挑战的措辞
- 🟡 **需要准备**：涉及 internal 内容，需要想好脱敏讲法的部分
- 🟢 **优势**：素材扎实、可以主动引导话题的点

高风险项要给出建议：要么在面试前补齐素材，要么回到 `resume-tailor` 改弱措辞。

## 模拟面试

用户想练的时候：

- **一次只问一个问题**，等用户回答
- 根据回答追问，像真实面试官那样：答得含糊就追细节，答得好就换下一个话题
- 每 3～5 个问题后，给一次简短反馈：哪里讲得好、哪里含糊、哪里和简历对不上
- 用户回答里出现库中没有的新细节（比如一个数字、一次踩坑）时，**问一句要不要记进履历库**，同意的话补进对应的成果文件
- 结束时总结：最需要加强的 2～3 个点

语气可以有压力，但要专业，不要阴阳怪气。

## 收尾

`grill.md` 写进投递目录。告诉用户高风险项有几个，并建议花多少时间准备。
